# Changelog

Every notable change to the prov workspace, newest first. All eleven published
crates share one version number and one release, so this is the changelog for
all of them; the scope on a bullet (`**history**`, `**cli**`) says which surface
moved.

The `## Unreleased` region below is generated by `cargo xtask changelog --write`
from the commits since the last tag, and `cargo xtask release` cuts it into a
released section. Everything outside that region is handwritten and stays that
way — including a release intro, when a release wants a narrative rather than a
list. **Behavioural changes** is generated too, from `Behavioural-change:`
trailers on the commits themselves; write one on any commit a consumer would
notice after upgrading without editing a line of their own code.

One irregularity, recorded rather than tidied away: **0.5.0 went to crates.io on
2026-08-17 before it was tagged**, from a laptop rather than the release
workflow. The tag was added afterwards, at `1b27f4e` — the commit the published
crates name in their own `.cargo_vcs_info.json`, verified against the packaged
sources. Five of the eleven crates were packaged one commit earlier, at
`837e13f`, which differs from it by one line of `.gitignore` and nothing else.

## v0.7.0 — 2026-08-21

### Breaking

- **history** — retire the event store; the skiplist scopes historica ([`6d4b7f4`](https://github.com/diaryx-org/prov/commit/6d4b7f4312bc65063e55eadfcaf6982b5f938b1c))

### Uncategorised — triage before release

- Update Cargo.lock ([`37541b7`](https://github.com/diaryx-org/prov/commit/37541b73bf765edc759466032d5675183779088f))

### Behavioural changes

- The `history-capture`, `history-list`, `history-show`,
  `history-cat`, `history-diff`, `history-log`, `history-export`,
  `history-restore`, `history-prune`, `history-forget`, and `cache`
  commands are gone, along with the `--cache-dir`/`--no-cache` global
  flags; `history-skips` is the one history verb left. Existing event
  stores stay on disk and readable by hand (docs/history-format.md), but
  no command writes or reads them any more.

- `check` no longer validates a history store. The
  `HistoryIndexStale`, `HistoryBlobMissing`, `HistoryBlobOrphaned`, and
  `HistoryStoreUnlinked` findings are gone (with their JSON shapes), as
  are the `RebuildHistoryIndex` and `LinkHistoryStore` fixes; a
  historica-marked `history/` directory is parked out of every walk.

- The prov library lost the history verb surface
  (`HistoryStore`, `history_capture` through `history_forget`,
  `Uncaptured`/`uncaptured`) and the fixity-cache carriage
  (`set_fixity_cache`, `take_fixity_cache`, the builder's `fixity_cache`);
  `prov::history` now exports the skiplist vocabulary (`Skiplist`, `Skip`,
  `Reason`, `Standing`, `SkipHost`, `apply`). The `history` config axis
  keeps its spellings (`off`/`manual`) but now gates `history-skips
  --write` instead of capture.

### Changed

- **mutate** — the body guard opened a folder of notes to ask a question about paths ([`40bd85d`](https://github.com/diaryx-org/prov/commit/40bd85d184f0d0dc263d85163cb1640463179758))

### Behavioural changes

- `prov history-capture --dry-run` now succeeds on a
workspace with `history: off` instead of exiting 1 with "history is off for
this workspace". A script relying on that non-zero exit to detect the axis
should read `prov config history` instead. Under `off` the report adds one
stderr line saying no capture is going to take the files it lists; stdout —
the capture set, one path per line — is unchanged.

- `prov check` gains a finding kind and now scans the whole
tree rather than only reached directories, so a workspace that reported clean
can report findings and exit 1 — every one of them a document that is really
unreachable and really outside the capture set. A document that was reported as
an `Orphan` while declaring `part_of` at a reachable parent is now reported as
`MissingContainment` instead (one finding, not two), with a single derived
remedy rather than a list of candidate parents to choose between. Library
consumers matching on `prov::Finding` need an arm for the new variant.

- `Workspace::reparent` now answers with a `Reparented` value
rather than the unit type; a caller that discards the result needs no change, one
that matched on `Ok(())` does. Reparenting a child that already claims the given
parent now writes the parent's spanning entry when it is missing, where before it
was a silent no-op — a workspace repaired with `prov reparent` will gain the
`contents` entries those runs did not make. Reparenting away from a parent that is
no longer on disk now succeeds instead of failing with an I/O error.

- `prov --version` no longer prints the package version alone.
A binary built from anything other than this version's release tag now prints
the version followed by an abbreviated commit hash in parentheses — `prov 0.6.1
(8cc0436e)`. Builds from the tag, and builds from a source tree with no git
metadata (the crates.io tarball, docs.rs, distro packaging), are unchanged.
Anything parsing `--version` should take the first two whitespace-separated
fields rather than the whole line.

- `delete` and `recycle` no longer refuse the prose half of a
separated pair when the owning node is a markdown document with a `content:` key
in its frontmatter — a pair prov's own verbs will neither create nor combine.
Where the node is a whole-file metadata document, which is every pair `separate`
or `attach` produces, the refusal is unchanged. Callers see fewer reads: the
guard opens only whole-file neighbours, so a `Storage` that counts reads, or one
whose reads have side effects, sees one per sidecar in the directory rather than
one per document.

### Behavioural changes

- `ci/check-getting-started.sh` is unchanged and still runs
the guide's transcript, but the entry point is now `cargo xtask docs`, which
builds prov-cli first. Contributors running the old per-job cargo commands by
hand can keep doing so; `cargo xtask` lists what CI actually runs.

- `history-log` given a path now reports points after a
rename where it previously ended at `Gone`, so a caller counting change points
or reading the last state of a moved document sees a different answer — a more
complete one, but different. Rows reached that way are marked `(moved —
inferred)`, and the path-key footer no longer claims the lineage "stops at any
rename". `prov_history::Version` gains a public `inferred: bool` field, which
breaks exhaustive struct patterns and struct-literal construction downstream.
`history-log id:`<id>`` is unchanged in every respect.

- `discover` and `Workspace::root_document` no longer count a
document whose `generated_by` names prov among a directory's root candidates. A
workspace that was ambiguous purely because of its own `about` page now resolves
to its real root; one that genuinely holds two hand-written candidates is still
refused. A hand-authored root that happens to carry `generated_by: prov …` would
stop being discoverable — nothing but prov's own `about` generator writes that
byline, so this is a shape no workspace should have.

- `Workspace::loose_attachments` (and so `attach --all
--recursive`) no longer returns files under the history store's `events/` or
`blobs/`, or under the recycle bin's `items/`. A caller relying on it to
enumerate parked bytes must read the store's own index instead. The signature is

- `HistoryStore::capture` and `Workspace::history_capture`
take `CaptureNote<'_>` where they took `label: Option<&str>`. A caller passing
a label updates to `CaptureNote::labelled(label)`, and one passing `None` to

- `Graph::read_scope` and `Workspace::read_scope` return
`ReadScope` rather than `ReadScope<'_>` — the guard holds a share of the memo
instead of borrowing the graph. A caller naming the type in a signature drops
the lifetime; one that binds the guard to a local, as every caller in tree
does, is unaffected. The lifetime was also a weak argument that a scope cannot
be stashed and left open; that is now discipline rather than a type.

- `walk`, `tree_within`, `Workspace::census`/`walk`/
`reachable_files`, and the mutating verbs listed above now read each document
once per operation rather than once per pass. A `Storage` that counts reads,
or one whose reads have side effects, sees fewer of them. And a document
rewritten by something outside prov partway through one of these operations is
now read either wholly before or wholly after that write, where a later pass
could previously have picked up the new bytes while an earlier one held the
old.

- remove(edit) the read-back workaround fig 2.5.3 made unnecessary

`set_meta_in_text` wrote a mapping, re-parsed the whole document, compared
the value's kind at the path, and on a mismatch fell back to writing one
scalar leaf at a time and pruning whatever the old subtree had that the new
one did not. All of it existed because fig's editor created a path's missing
ancestors as inline flow, and a block value spliced into one came out as
`a: {b: - x}` — which re-reads as a string, not a list — while reporting Ok.

probing every shape prov can meet, there is no case where the direct write

- deps(twig) 2.7.0 — the Djot path the generator writes into now round-trips

`about.md` is authored as Markdown and transcoded by twig when a
workspace declares `content_format: djot`, so twig's Markdown→Djot
fidelity is the generated page's fidelity. Two gaps found while
evaluating it (diaryx-org/twig#1, #2) made that path lossy; both are
fixed here.

**Table headers survive the transcode.** The Markdown→Djot serializer
emitted a table's rows without the separator line under the header, so
the header row arrived as ordinary data and Djot→HTML produced `<td>`
where `<th>` belonged. The relation vocabulary — the page's densest and
most-consulted section — is a table, so a Djot workspace was getting the
one part a stranger scans hardest with its structure quietly removed.

Worth recording that half of what that issue reported was wrong: it also
claimed the Djot *parser* should recognize a spaced `| --- |` separator,
on the strength of the Markdown parser accepting it. Djot's canonical
implementation takes only the compact `|---|`, so the parser was right
and the report was not. The serializer now emits the compact spelling,
which is what the round-trip needed all along.

**Raw inline and block HTML keep their raw spelling.** `raw_inline` nodes
were serialized to Djot as bare text, so a reparse read them as ordinary
characters and HTML-escaped them — silently, with no error and no
`UnsupportedFormat`. The page's footer byline is wrapped in `<sub>`, so a
Djot workspace rendered `&lt;sub&gt;` in its prose. Djot spells raw
content `` `…`{=html} ``, which twig's parser already understood; only
the way out was missing.

This is why the generator kept its full markup vocabulary rather than
narrowing to constructs that transcoded cleanly. Dropping tables and the
`<sub>` footer would have degraded every workspace's page — including the
Markdown ones, which were never affected — to work around two bugs in a
sister project that could simply be fixed. Verified by round-tripping
both constructs through Markdown → Djot → parse → HTML rather than by
reading the changelog.

No regeneration follows: both worked examples and this repository's own
page are Markdown, and the fixes are on the Djot path. `prov about
--check` confirms the live page is byte-identical to what 2.3.0 produced. ([`dc2ab3a`](https://github.com/diaryx-org/prov/commit/dc2ab3aad6002b19bf9339d3e1aaf2db166bce23))

- typo in README contents ([`4cf87da`](https://github.com/diaryx-org/prov/commit/4cf87da60d2d8579b697ec19f74855f28f015f2d))
- make the registry reachable: linked from the root, hosted in any document

The .colophon/ dotfolder violated the crate's own thesis — a readable
registry that no link reaches is .obsidian/ with a nicer file format.
Reachability is the property, not just readability.

- relation: RelationSet gains a registry role (like spanning); the diaryx
  preset adds one("registry"). The pointer is an ordinary edge: shown by
  links, validated by check, discovered by Workspace::registry_path.
- document: config files are documents — .yaml/.yml/.json/.fig/.figl parse
  as whole-file metadata (MetaCarrier::WholeFile); Document.embed became
  Document.carrier { Fenced(EmbedType), WholeFile(Format) }. The registry
  is the first config-file citizen of the tree.
- edit: MetaEditor dispatches on carrier (fig::Embed for fenced blocks,
  fig::Editor for config docs); set/unset and all mutation link
  maintenance work on both shapes, comment-preservingly.
- index: FileIndex records live under the 'registry' key of whatever
  document the root's pointer targets — registry.yaml or the frontmatter
  of registry.md alike. Steady-state writes are per-record scalar upserts
  (whole-map splices can't round-trip every carrier); the first
  materialization on a bare host re-serializes for block one-record-per-
  line layout. Host title/part_of/comments/body survive every write.
- CLI: the workspace root is discovered by walking up from cwd (a .md
  document with metadata and no part_of; index.md/README.md win ties);
  paths re-anchor to it, so commands work from subdirectories. First
  'colophon id' bootstraps registry.yaml, self-described and linked from
  the root's own metadata. tree/check default to the discovered root.

Known fig follow-ups: embeds cannot splice block-map values (bare hosts
can), and editor value splices have no width/layout knob (short maps
render flow) — both worth upstreaming eventually. ([`c3f35f2`](https://github.com/diaryx-org/prov/commit/c3f35f25ba64fc46fb5f9d85e606dfc84a1ca569))
